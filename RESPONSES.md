# Отчёт по ревью и исправлениям ТЗ «RoboMeg»

В данном документе приводится сводка замечаний ревьюеров (Сорокина С. и Резниченко И.), а также нюансов, выявленных в ходе самостоятельного аудита первой версии технического задания (`SPEC_1.md`). Для каждого случая указана категория проблемы (**неоднозначно**, **не покрыто тестами**, **противоречиво**), суть замечания и принятое решение по исправлению.

---

## 1. Замечания ревьюеров

### 1.1. Замечания ревьюера Сорокина С.

1. **Неоднозначность приоритета исключений в `hunt_fish`**
   - **Категория:** неоднозначно
   - **Суть замечания:** При вызове `hunt_fish()` в состоянии, когда у мегалодона достаточный заряд (`energy = 60`), но при этом он находится в воздухе после прыжка, возникала неопределенность: какое исключение должно выбрасываться первым — `RoboMegNotHungry` или `UnsafeHuntingZone`.
   - **Как исправили:** В раздел 6.2 ТЗ добавлен строгий детерминированный порядок проверок для метода `hunt_fish()`: сначала проверяется безопасность зоны (воздух / дистанция после прыжка), затем уникальность координаты (наличие рыбы), и только в конце — уровень энергии.

2. **Непокрытые тестами сценарии для `pass_island` в `TC-M-010`**
   - **Категория:** не покрыто тестами
   - **Суть замечания:** Таблица трассируемости утверждала, что базовый тест `TC-M-010` проверяет корректность нехватки энергии и точного обнуления как для `move`, так и для `pass_island`, однако фактически в теле кейса вызовы `pass_island` отсутствовали.
   - **Как исправили:** Разделили проверки: `TC-M-010` оставлен для метода `move`, а для `pass_island` добавлен отдельный тестовый кейс `TC-M-010b`, проверяющий выброс `EnergyEmpty` и обнуление заряда до `0.0` как при прыжке, так и при обплыве острова по полукругу.

3. **Противоречие в правилах прыжка при равенстве расстояния (`jump_length_km`)**
   - **Категория:** противоречиво
   - **Суть замечания:** В методе `move` прыжок по воздуху разрешался при условии `distance_km <= jump_length_km`, в то время как в методе `pass_island` условие перепрыгивания острова требовало строгого неравенства (`diameter_km < jump_length_km`).
   - **Как исправили:** Унифицировали логику по всему ТЗ: прыжок по воздуху разрешён во всех методах при условии `distance_km <= jump_length_km`. Остров с диаметром, равным длине прыжка, теперь успешно перепрыгивается.

### 1.2. Замечания ревьюера Резниченко И.

1. **Цепочка последовательных прыжков без возвращения в воду**
   - **Категория:** противоречиво / неоднозначно
   - **Суть замечания:** Физическая модель мегалодона подразумевает совершение прыжков хвостовым плавником из водной среды. Однако логика не запрещала вызывать повторный прыжок, находясь в воздухе (`is_airborne == True`).
   - **Как исправили:** В правила методов `move` и `pass_island` добавлено жесткое требование: прыжок в воздушную среду (`terrain == "air"`) возможен **только из воды** (`is_airborne == False`). При попытке прыгнуть из воздуха выбрасывается доменное исключение.

2. **Погрешность вычислений с плавающей точкой (`float`) при точном исчерпании заряда**
   - **Категория:** неоднозначно
   - **Суть замечания:** Из-за особенностей представления чисел с плавающей точкой в Python (например, `0.3 - 0.1 - 0.1 - 0.1 != 0`), при точном списании энергии до нуля мог возникать отрицательный остаток вида `-2.77e-17`, что приводило к ложному срабатыванию исключения `EnergyEmpty`.
   - **Как исправили:** Введено правило обязательного округления всех промежуточных вычислений энергии, координат и времени до 6 знаков после запятой (`round(val, 6)`).

3. **Несоответствие предусловия в тестовом кейсе `TC-M-015`**
   - **Категория:** не покрыто тестами / противоречиво
   - **Суть замечания:** В тестовом кейсе `TC-M-015` объект инициализировался с `energy = 100`, при этом ожидалось исключение `UnsafeHuntingZone`. Однако при энергии $\ge 50$ срабатывала проверка голода (`RoboMegNotHungry`).
   - **Как исправили:** Предусловие в `TC-M-015` было исправлено: начальная энергия установлена на уровень `energy = 40.0`, что позволяет корректно проверить именно запрет охоты в небезопасной зоне.

## 2. Нюансы, выявленные самостоятельно (самоаудит)

1. **Неполное покрытие проверки неизменяемости атрибутов (read-only)**
   - **Категория:** не покрыто тестами
   - **Описание:** В спецификации заявлялось, что все 8 атрибутов класса доступны только для чтения, но тестовый кейс `TC-M-005` проверял попытку изменения только для двух атрибутов.
   - **Как исправили:** Расширили `TC-M-005` с помощью параметризации, покрыв тестами попытку записи в каждый из 8 публичных атрибутов.

2. **Отсутствие проверки текстов исключений в тестах**
   - **Категория:** не покрыто тестами
   - **Описание:** Тесты проверяли сам факт выброса исключений (`TypeError`, `ValueError`, доменные ошибки), но не проверяли соответствие текстов сообщений об ошибках таблице 6.2.
   - **Как исправили:** Добавили отдельный тестовый кейс `TC-M-027`, верифицирующий тексты сообщений для всех доменных и стандартных исключений.
